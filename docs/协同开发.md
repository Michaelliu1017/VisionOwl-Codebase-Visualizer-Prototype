## 2. 并行开发模式


## 3. 通信协议总则

| 项 | 约定 |
|---|---|
| BaseURL | 开发期 `http://114.55.60.94:8080`;Desktop 通过环境变量 `VITE_API_BASE` 配置,代码中禁止写死 |
| 前缀 | 业务接口一律 `/api/...`;Webhook 为 `/webhook/github`(不带 /api) |
| 认证 | `Authorization: Bearer <JWT>`;登录/注册/health/webhook 之外全部必带 |
| JWT | HS256,`{ sub: userId, exp }`,有效期 7 天;失效返回 401 |
| Content-Type | 请求与响应均 `application/json; charset=utf-8`(SSE 除外) |
| 时间 | 一律 ISO 8601 UTC 字符串,如 `2026-08-04T12:00:00Z` |
| ID | 一律 uuid v4 字符串 |
| 分页 | 请求 `?limit=20&cursor=<opaque>`;响应 `{ "items": [...], "nextCursor": "..." | null }` |
| CORS | MVP 允许 `*`(Electron 渲染层 origin 不固定);安全靠 Bearer,登录接口做限速 |
| 版本头 | 响应带 `X-Contract-Version: 1.0`;Desktop 请求带 `X-Client-Version` |
| 成功响应 | 2xx 直接返回资源对象/列表,**不包 data 壳** |
| 删除类 | 成功返回 `204 No Content` |
| 异步受理 | 返回 `202` + 资源当前态(如创建任务) |

### 3.1 统一错误格式

任何非 2xx 响应体:

```json
{ "error": { "code": "FORBIDDEN", "message": "人类可读信息", "details": {} } }
```

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_FAILED` | 参数缺失/格式错误(details 里给字段) |
| 401 | `AUTH_REQUIRED` | 未登录或 token 过期 |
| 403 | `FORBIDDEN` | 角色不足 / 非成员访问 Project |
| 404 | `NOT_FOUND` | 资源不存在(含无权可见,防枚举) |
| 409 | `DUPLICATE` | 重复创建(任务去重命中、重复绑定等) |
| 410 | `INVITATION_INVALID` | 密钥错误或已撤销 |
| 429 | `RATE_LIMITED` | 登录限速、chat 限流 |
| 500 | `INTERNAL` | 兜底,message 不得泄漏堆栈 |

### 3.2 共享枚举(两端硬编码必须一致)

```
role:        owner | editor
job.type:    full | incremental
job.status:  queued | running | succeeded | failed | canceled
doc.scope:   global | module
doc.type:    dingtalk | external | generated
doc.status:  ok | maybe_stale
node.kind:   domain | module | class | function | interface | config
             | infra.redis | infra.mq | infra.db | external
edge.type:   call | dependency | read | write | publish | consume | implement
annotation.targetKind: node | edge
```


**无 installationId 时的行为**:worker 走公开 HTTPS 克隆(`https://github.com/<repoFullName>.git`),

同时返回 `repositoryCommits`，记录本次联合分析中每个 `repositoryId` 对应的冻结 commit。

## 5. 实时事件(SSE)

```
GET /api/projects/:id/events
Accept: text/event-stream        (带 Bearer;EventSource 不支持自定义头时
                                  允许 ?token=<jwt> 查询参数,后端两种都收)
```

- 心跳:每 25s 发送注释行 `: ping`
- 每条事件带自增 `id:`,支持 `Last-Event-ID` 尽力续传(断线重连丢事件可接受,客户端以拉取兜底)
- 格式:`event: <type>` + `data: <单行 JSON>`

| event | data 载荷 |
|---|---|
| `job.created` | Job |
| `job.progress` | `{ "id", "status": "running", "progress": 42 }` |
| `job.succeeded` / `job.failed` | Job(failed 含 error) |
| `graph.version.switched` | GraphVersion |
| `document.created/updated/deleted` | Document(deleted 仅 `{ "id" }`) |
| `annotation.created/updated/deleted` | Annotation(deleted 仅 `{ "id" }`) |
| `member.joined` | `{ "user": {"id","name"}, "role" }` |

**Desktop 消费规则**:事件只做"提醒 + 局部刷新"信号;数据一致性以随后的 REST 拉取为准(事件可丢,拉取不可错)。

## 6. AI 对话流协议

```
POST /api/projects/:id/chat            [editor]
Accept: text/event-stream
req { "question": "修改它会影响哪些组件?",
      "nodeId": "module:modules/booking" | null,     // 画布当前选中,可空
      "sessionId": "uuid" | null }                    // 续接会话传入
```

响应为 SSE 流,事件序列:

```
event: chat.meta      data: { "sessionId": "uuid" }            // 首帧必发
event: chat.delta     data: { "text": "增量文本片段" }           // 0..n 次
event: chat.evidence  data: { "items": [ { "file": "modules/booking/src/x.ts",
                                            "startLine": 24, "endLine": 40,
                                            "symbol": "BookingPaymentAdapter" } ] }
event: chat.action    data: { "type": "highlight",
                              "nodeIds": ["module:..."], "edgeIds": ["e:..."] }
event: chat.done      data: { "sessionId", "credits": 1.2, "inferred": false }
event: chat.error     data: { "code": "INTERNAL|RATE_LIMITED", "message": "..." }
```

约定:

- `chat.action(highlight)` 由 Desktop 直接驱动画布高亮(等价用户选中,但不改变用户的 selectedNodeId,用独立的 `aiHighlight` 状态层,Esc 清除)
- `inferred: true` 时 Desktop 在回答尾部渲染琥珀提示「含推断内容,待人工确认」
- 后端 MVP 可先用**规则回答**(查图谱邻接表拼答案)占位,P2 再接 qodercli;**流协议不变**
- 单会话 `--max-turns 15`,超限返回 chat.error RATE_LIMITED

## 7. graph.json 获取与校验(两端职责)

- Schema 唯一定义:spec.md §8;两端各自实现校验(后端入库前 AJV 校验;前端渲染前轻校验:节点 id 唯一、边端点存在、枚举合法)
- **前端必须把 graph.json 当不可信输入**:所有 name/summary/path 渲染前转义(Electron 下 XSS = RCE 风险)
- 节点 id 约定:`<kind前缀>:<路径>`,如 `module:modules/booking`、`infra:redis`;边 id:`e:<source>-><target>:<type>`
- 后端保存版本时:graph_versions 行 + 产物文件(MVP 存本地 `/data/artifacts/{projectId}/{sha}/graph.json`,二期迁 OSS,`artifactUrl` 语义不变)

### 9.3 部署接入(ECS 现状,务必遵守)

- ECS 上已有 compose 栈 `infra`:`infra-gateway-1`(nginx, **当前只绑 127.0.0.1:8080**)→ `infra-cloud-1`(:17800)→ `infra-postgres-1`(卷 `infra_visionowl-postgres`)
- Cloud Agent 的服务**就是** `infra-cloud` 的正式实现:替换其镜像内容,不要另起一套栈
- 需要你做的三处基础设施变更(都属于你的职责):
  1. compose 增加 `redis:7-alpine`(内网,不暴露公网端口)
  2. gateway 发布改为 `0.0.0.0:8080`(桌面端要从外网访问;放开后登录接口必须有限速)
  3. 挂载 `/data/artifacts` 进 cloud 容器(产物目录)
- **网络红线**(实测):`registry-1.docker.io` 不通——基础镜像一律走 ACR/阿里镜像源;`raw.githubusercontent.com` 不通——任何安装脚本不得依赖它;npm registry 与 github.com 可用
- 不得影响现有 postgres 卷数据;改动 compose 前先 `docker compose config` 校验

## 12. 联调检查点(可执行验收)

```bash
BASE=http://114.55.60.94:8080

# —— CP1:骨架与认证 ——
curl -sf $BASE/api/health | grep '"contract":"1.0"'

  -d '{"email":"owner@demo.dev","password":"demo1234"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# —— CP2:项目与图谱(Desktop 切真实 API 的前提) ——

  | python3 -c 'import sys,json;print(json.load(sys.stdin)["items"][0]["id"])')
curl -sf $BASE/api/projects/$PID/graph/current -H "Authorization: Bearer $TOKEN"
curl -sf $BASE/api/projects/$PID/graph/versions/1/artifact -H "Authorization: Bearer $TOKEN" \
  | python3 -c 'import sys,json; g=json.load(sys.stdin); \
assert len(g["nodes"])==17 and len(g["edges"])==31, "demo 图谱不符"; print("graph OK")'
curl -sf $BASE/api/projects/$PID/documents -H "Authorization: Bearer $TOKEN"
curl -sf $BASE/api/projects/$PID/annotations -H "Authorization: Bearer $TOKEN"

# —— CP2.5:SSE(另开终端保持连接,执行一次批注创建应收到事件) ——
curl -N "$BASE/api/projects/$PID/events?token=$TOKEN" &

  -H 'Content-Type: application/json' \
  -d '{"targetKind":"node","targetId":"module:modules/catalog","body":"联调测试批注"}'

# —— CP3:邀请闭环(第二账号) ——

  -H 'Content-Type: application/json' -d '{}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["key"])')
T2=$(curl -sf -X POST $BASE/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"editor@demo.dev","password":"demo1234"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
```

## 13. 契约变更流程

1. 动机写清楚:哪个端点/字段、为什么、是否破坏性
2. 修改本文档对应小节,顶部契约版本号 +0.1(破坏性变更 +1.0),并在文末「变更记录」追加一行
3. commit 前缀 `contract:`,该 commit **只允许**包含 `协同开发.md` / `spec.md` 的改动
4. 双方在各自下一个 commit 中跟进实现;未跟进前,新增字段两端都必须容忍(未知字段忽略)

**向后兼容加法**(新增可选字段、新增端点、新增事件类型)可先改文档后通知;**破坏性变更**(改名/删字段/改语义/改状态机)必须双方确认后才可合入。
