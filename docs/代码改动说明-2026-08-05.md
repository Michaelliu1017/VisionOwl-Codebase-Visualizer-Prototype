## 2. 当前系统结构

```text
Electron 桌面端
  ├─ React 图谱/项目/Agent UI
  ├─ SSE 订阅云端项目事件
  └─ Electron 主进程调用本机 DWS CLI
          │
          ▼
ECS Nginx Gateway :8080 / Host Nginx :443
          │
          ▼
Cloud API（Node.js/Fastify）
  ├─ 项目、仓库、任务、图谱、文档、Agent API
  ├─ GitHub Webhook
  └─ SSE 事件广播
          │
          ├─ PostgreSQL：业务数据、项目、任务、图谱版本、文档元数据
          ├─ Redis：任务流、锁、Agent/Docgen 状态、事件和回答缓存
          └─ Worker
                └─ Docker Runner（Qoder CLI + Skills + Scanner）
```

## 3. 桌面端改动

### 3.1 云端模式和登录状态

- 增加 `dev:cloud` 启动脚本，通过 production mode 使用真实云后端，不再默认进入 Mock API。
- 登录页明确显示当前是 Mock 模式还是云端模式。
- 增加生产环境 API 地址配置，桌面端可直接连接 ECS 后端。

### 3.2 项目创建、公开仓库和分支选择

- 新建项目流程从两步扩展为三步：创建项目、检查并绑定仓库、明确点击开始分析。
- 支持输入完整 GitHub URL 或 `owner/repo`。
- 绑定前调用云端 GitHub 公共 API 校验仓库是否存在、是否公开，并加载真实分支列表和每个分支的 HEAD SHA。
- 分支由下拉框选择，避免用户输入不存在的分支。
- 仓库绑定和分析触发拆开，用户可以清楚看到任务进入 Redis、Worker、Runner 的过程。

### 3.3 项目状态、图谱刷新和 Webhook 提示

- 项目 Store 改为真实加载项目详情、当前图谱、图谱产物、文档、批注和最近任务。
- 记录最后一次打开的项目，桌面端重启后恢复用户工作区。
- 新增项目级 SSE 订阅和连接状态显示。
- 收到 `repository.push.received` 后立即弹出“检测到代码变更”。
- 收到 `job.created`、`job.progress`、`graph.version.switched`、`job.succeeded` 后实时更新分析窗口、任务进度和图谱。
- SSE 异常时保留任务轮询兜底；应用重新打开时会恢复 queued/running 任务。
- 状态栏显示云端地址、SSE 在线状态、当前图谱版本、对应 commit SHA 和分析队列状态。
- 切换项目时使用 epoch 防止旧请求覆盖新项目状态，并立即清除上一个项目的图谱和文档。

### 3.4 Agent Chatbox

- Agent 请求不再只根据图谱返回规则答案，而是携带项目、commit、节点路径和问题进入云端 Qoder 任务。
- 每个项目保存 Agent sessionId，连续问答使用同一逻辑会话并执行 turn 限制。
- 支持 `chat.status` 中间状态，界面显示排队、准备源码、命中源码缓存、阅读源码和整理回答等阶段。
- 显示回答来源：`Qoder 云端回答` 或 `规则引擎降级回答`。
- 新增 Markdown 渲染组件，支持标题、列表、代码、表格、链接等 GFM 格式，不再直接展示 `#` 等 Markdown 符号。
- 修复 SSE Markdown 分片拼接，保证分片合并后与原始 Markdown 完全一致。
- Agent 快捷按钮与模块选择联动；“生成文档”改为独立动作，不再伪装成普通问答。

### 3.5 钉钉 DWS 身份和文档发布

- Electron 主进程新增 DWS CLI 封装，支持查询状态、登录、切换身份、退出身份、创建文档和覆盖更新文档。
- 登录调用 DWS 自带的系统浏览器 OAuth/扫码流程，不在应用内伪造二维码，也不要求用户复制设备码到另一个网址。
- preload 仅暴露白名单 IPC，渲染进程不能直接访问 Node.js 或执行任意命令。
- 新增钉钉设置弹窗，首次生成文档时如果没有可用身份会要求连接；后续可切换或移除身份。
- 每个 DWS profile 可以保存工作区和文件夹目标；目的地只保存在本机，不把 OAuth Token 上传到 VisionOwl 数据库。
- 发布时，有已有钉钉 nodeId 就使用 overwrite 更新原文档；没有 nodeId 就创建新文档。
- 云端只保存文档 URL、nodeId、产物键和同步状态，不保存 DWS Token。

### 3.6 文档和图谱 UI

- 节点详情面板支持挂载钉钉文档、删除挂载和查看状态。
- 自动生成文档可在应用内读取云端 Markdown 快照。
- 图谱中的文档卡和详情面板统一使用真实文档数据。
- 增加生成中、同步失败、可能过期等状态样式。

## 4. 云后端改动

### 4.1 公开 GitHub 仓库接入

- 新增 GitHub 公共仓库客户端，提供仓库检查、分支列表和分支 HEAD SHA 查询。
- GitHub App installationId 改为可选：公开仓库不需要 GitHub App Token，Runner 使用匿名 HTTPS 克隆。
- 绑定公开仓库时后端再次校验仓库和分支，防止客户端绕过检查。
- 私有仓库仍需要 GitHub App，当前演示闭环只保证公开仓库。

### 4.2 GitHub Webhook 增量分析

- Webhook 保留 HMAC SHA-256 验签和 delivery ID 幂等。
- push 与项目绑定的 repo/branch 匹配后，立即发送 `repository.push.received` SSE 事件。
- 创建 incremental job，记录 base SHA 和 target SHA，并投递 Redis Stream。
- 同一 SHA 已存在图谱版本时直接复用，不重复消耗 Qoder credits。
- 连续 push 的去抖逻辑会更新尚未开始的 queued 任务；如果旧任务已经 running，则新建最新 SHA 任务，保证最终图谱不会停留在旧提交。
- Worker 完成后更新仓库绑定 SHA、保存图谱版本并广播 `graph.version.switched` 和任务完成事件。

### 4.3 Redis 任务和可靠性

- Redis Stream 消息增加 `analyze`、`chat`、`docgen` 三种 kind，由同一个 Worker 消费组分派。
- 增加 Agent 任务状态、文档生成任务状态和 Agent 回答缓存。
- 增加 Redis ready 等待，避免应用启动时连接尚未 ready 导致静默丢任务。
- 增加 `XAUTOCLAIM`，Worker 可捞回长时间未确认的任务。
- 分布式锁增加唯一 owner token，并通过 Lua 只释放自己的锁，避免超时后误删其他 Worker 的锁。
- ECS Redis 改为 AOF everysec，并挂载持久卷。
- SSE Redis Pub/Sub 在重连后自动重新订阅。

### 4.4 Runner、扫描和图谱

- Worker 在 runner 模式下通过宿主机 Docker socket 拉起一次性 Runner 容器。
- Runner 支持 `analyze`、`chat`、`docgen` 三种模式。
- 克隆逻辑增加 HTTP/1.1、postBuffer、浅克隆和部分克隆退化重试，以适配 ECS 到 GitHub 的网络环境。
- 对指定 target SHA 做精确 checkout 和校验，防止分析错误提交。
- Scanner 增强 manifest/workspace 和普通源码目录发现，排除 venv、site-packages、`__pycache__` 等无关目录。
- 图谱增加源码证据、import 关系、基础设施节点和变更影响计算。
- 保存 graph、facts、impact、架构文档等产物；图谱版本切换和 commit SHA 一一对应。
- 支持 local 和 OSS 两种 Artifact Storage 实现；OSS 使用 `ali-oss`，但当前 ECS 尚未启用 OSS。

### 4.5 Agent 源码问答

- 云端先生成受图谱事实约束的草稿，再将问题投递到 Redis，由 Worker 拉起 chat Runner。
- Chat Runner 在当前图谱 commit 的真实源码目录内执行 Qoder CLI，可读取选中模块文件、函数实现和调用细节。
- 对小模块进行预检索，直接把相关源码块交给单轮 Qoder，减少无意义多轮搜索。
- 对较复杂问题保留 repository-understanding skill 搜索能力。
- 每个 `project + commit + node + question` 生成回答指纹，命中 Redis 缓存时直接返回。
- 分析完成后保留当前 commit 的短期只读源码缓存；后续问答和文档生成跳过 GitHub 下载。
- 源码缓存按 TTL 清理，默认 24 小时；Runner 仍是一次性容器，不是常驻 Agent 容器。
- Qoder 不可用、队列异常或超时时自动降级为规则回答，并在 UI 明确标注，避免把降级答案伪装成源码分析。
- 增加 Qoder chat model、turn、输出 token、超时和回答缓存 TTL 配置。

### 4.6 文档生成和自动更新

- 新增模块文档生成 API、任务查询、待发布内容读取和发布确认 API。
- Docgen Runner 使用 repository-understanding 与 docs-sync skill 读取当前 commit 的真实模块源码，生成 Markdown。
- Markdown 快照保存到 Artifact Storage，PostgreSQL 保存文档元数据和历史 revision。
- 生成完成后云端发送 `document.publication.ready`，桌面端调用本机 DWS 创建或覆盖钉钉文档，再回调云端确认。
- 增量分析计算 affectedNodeIds 后，将相关挂载文档标记为 `maybe_stale`。
- 对 affectedNodeIds 上已经存在的 AI 模块文档，自动创建 docgen 任务；生成后使用原 dingtalkNodeId 覆盖更新同一篇钉钉文档。
- 每次分析都会更新全局“架构总览”云端 Markdown 快照。
- 同步失败会记录 `sync_failed` 和错误信息，不会把失败状态伪装成成功。

### 4.7 数据库和钉钉连接模型

- 新增 `dingtalk_connections` 表和默认身份唯一索引。
- `document_links` 增加 AI 生成标记、Artifact Key、钉钉连接 ID、钉钉 nodeId 和同步错误字段。
- 数据迁移可识别旧 `visionowl://artifact/` 文档并补齐 generated_by_ai 与 artifact key。
- 云端实现了一套 DWS connection API 和服务，但当前桌面演示主链路使用 Electron 本机 DWS，Token 不上传云端。

### 4.8 构建和部署

- Cloud 和 Runner 镜像改用 pnpm 锁文件安装依赖。
- Cloud 镜像安装 Qoder CLI；Runner 镜像包含 Qoder CLI、Python、Scanner 和 Skills。
- Debian apt 源切换到阿里云镜像以适配 ECS 网络。
- Worker 挂载 Docker socket、Docker CLI、Artifact 和 Workspace 目录。
- Nginx/SSE 增加禁用缓冲、流式 CORS 和心跳支持。
- 新增 OSS、源码缓存、Agent 缓存和 DWS 相关环境变量示例。

## 5. 自动更新挂载文档的准确边界

| 文档类型 | Git push 后行为 | 是否自动覆盖钉钉原文档 |
| --- | --- | --- |
| 全局“架构总览（AI 自动维护）” | 每次成功分析都会更新云端 Markdown Artifact | 否，当前是 VisionOwl 内部 generated 文档 |
| AI 生成的模块钉钉文档 | 模块受影响时自动重新运行 Docgen | 有条件：桌面端在线且存在可用默认 DWS 身份时，按原 nodeId overwrite |
| 用户手工挂载的钉钉/外部文档 | 受影响时标记 `maybe_stale` | 否，不自动改写用户手工维护的文档 |

因此当前答案是：代码中已经有“受影响模块的 AI 文档自动重生成并覆盖钉钉文档”的链路，但它不是无条件的后台能力。

当前限制：

1. 必须先对模块执行过一次“生成文档”，形成 `generated_by_ai=true` 的模块文档；没有模块文档时 push 不会凭空给所有模块创建钉钉文档。
2. 钉钉发布发生在 Electron 本机，因为 DWS 身份和 Token 保留在用户电脑；桌面端需要在线并连接默认 DWS profile。
3. ready_to_publish 状态在 Redis 中保留约 2 小时，但当前没有“列出所有待发布任务”的恢复 API；若桌面端错过 SSE、云端重启或离线过久，自动发布可能遗漏。
4. 用户手工挂载的文档只会标记可能过期，不会自动覆盖。
5. 钉钉组织如果未开通 DWS CLI 数据访问权限，创建/更新会失败并要求重新授权或管理员开通权限。

PyBanner 当前只存在一篇全局“架构总览”，没有 AI 模块钉钉文档，因此本次 push 已更新全局架构文档和图谱，但没有可自动覆盖的模块钉钉文档。

## 6. ECS 当前真实运行状态

### 6.1 VisionOwl 后端数量

ECS 当前只有一套正在运行的 VisionOwl Compose 项目：`infra`，配置文件为 `/opt/vo/infra/compose.yaml`。

| 服务 | 容器 | 角色 |
| --- | --- | --- |
| cloud | `infra-cloud-1` | VisionOwl Cloud API，Node.js `dist/index.js` |
| worker | `infra-worker-1` | VisionOwl Worker，Node.js `dist/worker/index.js` |
| gateway | `infra-gateway-1` | 容器 Nginx，对外发布 `8080` |
| redis | `infra-redis-1` | 任务队列、缓存和事件 |
| postgres | `infra-postgres-1` | 当前业务数据库 |

如果按“应用后端进程”计数，是 2 个：Cloud API 和 Worker；如果按完整 Compose 服务计数，是 5 个。

宿主机 Nginx 的 `443` 反向代理到 `127.0.0.1:8080`，因此 `443` 和 `8080` 最终访问的是同一套 VisionOwl 后端，不是两套后端。宿主机 `80` 目前服务 `/root/website` 静态站点，不属于 VisionOwl Cloud API。

`/opt/visionowl` 是旧代码目录，但没有对应 Node、PM2 或 Docker 服务在运行；当前真正部署并运行的是 `/opt/vo`。

### 6.2 当前数据面

- `ANALYZER_MODE=runner`，正在使用真实 Docker Runner。
- Qoder Token 已配置，Webhook Secret 已配置。
- PostgreSQL host 为 Compose 内部服务 `postgres`，当前不是阿里云 RDS。
- `ARTIFACT_STORAGE=local`，当前产物写在 ECS `/data/artifacts`，不是 OSS。
- OSS endpoint/bucket 当前未配置。
- Redis 使用 Compose 内部服务 `redis`。

代码已经具备 OSS 存储适配，但要满足最初“RDS PostgreSQL + OSS”的目标，还需要配置 RDS 连接串、OSS 凭据和 `ARTIFACT_STORAGE=oss`，再执行迁移和数据转移。

## 10. 同步和部署原则

- `/root/alitest` 作为 ECS 上的完整源码镜像，用本地工作区覆盖同步。
- 同步时排除 `.git`、`node_modules`、构建产物、缓存和本地日志，避免上传无关大文件。
- 不用本地示例环境覆盖 ECS 的 `/opt/vo/infra/.env`，生产 Secret、数据库密码、Qoder Token 和 Webhook Secret继续留在服务器。
- 真正运行的 Cloud 部署目录是 `/opt/vo`；源码镜像同步后，需要把 Cloud、Infra 和 Skills 更新到 `/opt/vo`，重建 Cloud/Runner 镜像并滚动更新 cloud/worker/gateway。
- 更新前保留备份；迁移只执行向前兼容的 `IF NOT EXISTS` SQL。
