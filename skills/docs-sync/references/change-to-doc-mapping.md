# 变更 → 文档影响判定细则

Phase 1 的逐类判定规则。每条提取的变更登记为：

```
{ 类别, 代码证据: path:line 或 hunk, 旧事实 → 新事实, 意图来源: commit/PR 或 "无" }
```

## 判定总原则

- 判定对象是 **hunk 的语义**，不是文件名。同一文件里可能同时有文档可见变更与噪音。
- 一个 hunk 可命中多个类别（如新增事件字段同时是"事件契约"与"导出契约"），逐类登记，后续匹配互不合并。
- 删除与新增同权重：**删掉的承诺**（移除导出、下线路由、删除事件字段）比新增更容易漏，文档里对应内容需要删除或标记废弃。

## 逐类识别规则

### 1. 导出契约

**看什么**：模块公共入口文件（`index.ts`、`__init__.py`、`mod.rs`、`api/` 收口点）的 diff；以及被入口 re-export 的符号的公共签名变化。

**判定**：
- 入口新增/移除 `export` → 可见。
- 深层文件的函数签名变化：先确认该符号是否从入口可达；不可达（私有实现）→ 噪音。
- 仅类型收窄/放宽但调用方式不变 → 可见但降级为低优先级（文档若未写签名细节则无需改动）。

**易漏**：`export type` 与 `export *` 的间接导出；重导出链上游改名导致下游契约实际变化。

### 2. 业务规则常量

**看什么**：策略类、校验函数、守卫子句中的字面量与比较边界；错误消息文本；枚举成员。

**判定**：
- 比较边界值变化（`> 8` → `> 10`）、时间窗口（`30 * 60 * 1_000`）、开关默认值 → 可见。
- 错误消息文本变化：若文档/流程图引用了消息原文 → 可见；否则噪音。

**易漏**：规则常量常被文档**语言化**（"between 1 and 8 seats"、"thirty minutes before"），检索时必须覆盖数字与数词两种形态（含中英文：8 / eight / 八）。

### 3. 路由 / 端点

**看什么**：路由注册处的 method、path、路径参数、请求/响应 payload 类型；中间件挂载（鉴权要求变化）。

**判定**：
- method/path 增删改 → 可见。
- payload 字段增删 → 可见（同时检查是否也命中"事件契约"或"导出契约"）。
- 仅 handler 内部实现重构、响应内容不变 → 噪音。

### 4. 事件契约（双侧传播）

**看什么**：事件类型定义（字段、类型名、topic/stream 常量）；`publish/send/XADD` 调用点；`subscribe/consumer/handler` 注册点。

**判定与传播**：
- 字段增删、事件改名、topic 常量变化 → 可见，且**必须同时检查发布侧与全部消费侧**的模块文档、架构文档中的事件流描述、涉及该事件的时序图。
- 新事件发布 → 架构图可能新增边；事件下线 → 对应边与流程段落删除。

消费侧定位方法：按事件类型名与 topic 常量全仓库检索，不能只看 diff 内出现的文件。

### 5. 模块依赖边

**看什么**：跨包 import 的**首次出现**或**完全消失**（不是每次 import 的增减）。

**判定**：
- 模块 A 的 diff 中新增了对模块 B 公共入口的 import，且 A 此前没有任何文件 import B → 新依赖边，可见。
- diff 移除了 A→B 的最后一条 import（需全仓库确认剩余为零）→ 依赖边消失，可见。
- A→B 已有依赖，只是又多了一个 import 点 → 噪音。

**质疑项触发**：新边违反架构文档明文声明的依赖规则（如"路由文件不得直接执行 SQL"）时，除更新文档外，必须在报告的质疑节单独列出——这可能是文档该改，也可能是代码越界，由人裁决。

### 6. 模块生命周期

**看什么**：workspace 声明（`package.json workspaces`、`pnpm-workspace.yaml`、`go.mod`、`settings.gradle`）成员增删；包名变更；新增部署单元（Dockerfile、compose service）。

**判定**：全部可见。新模块 → 架构图节点、模块文档目录（ADD 一篇最小模块文档或列入报告）、README 目录树；模块删除 → 反向清理所有引用。

### 7. 存储 schema

**看什么**：migration/DDL 文件；ORM 实体字段；缓存键格式字符串；新的表/集合/流名字面量。

**判定**：
- 新表/列、表归属模块变化 → 可见，对应架构文档"持久化所有权"类表格。
- 缓存键格式变化（`catalog:published` → `catalog:v2:published`）→ 可见。
- 仅索引调整、字段注释 → 噪音（除非文档写了索引策略）。

### 8. 配置与环境

**看什么**：`.env.example`、配置 schema、`process.env.X` / `os.environ` 读取点的增删、默认值变化。

**判定**：新增必填环境变量 → 可见且高优先级（直接影响他人能否启动）；可选项默认值变化 → 可见；仅重排 `.env.example` 顺序 → 噪音。

### 9. 命令与脚本

**看什么**：`package.json scripts`、`Makefile`、`Dockerfile`、CI 中面向人的命令、compose 服务名与端口。

**判定**：命令名/参数/端口变化 → 可见，对应 README 安装/运行/测试段与部署文档。CI 内部步骤重构且对人执行方式无影响 → 噪音。

### 10. 重命名 / 移动

**看什么**：`git diff -M` 输出的 `R` 状态行（必须带 `-M`，否则重命名会伪装成一删一增，触发错误的"模块删除"判定）。

**判定**：
- 文件重命名、目录移动 → 检索全部文档中的旧路径（链接、目录树代码块、行内引用），逐一替换。
- 重命名 + 内容修改（相似度 < 100%）→ 拆成两条：一条重命名传播，一条按内容 diff 走其余类别判定。
- 导出符号名不变、仅文件名变化 → 模块文档中按符号引用的句子不需要动，只改路径引用。

## 噪音清单（明确不触发）

- 格式化、lint 自动修复、import 排序
- 注释与文档字符串措辞（除非文档直接摘录了该注释）
- 私有函数重构、局部变量改名（导出面不变）
- 测试文件内部的断言细节（测试**命令**变化除外）
- 依赖 lockfile 的传递性更新、patch 版本升级（major 升级若改变使用方式则可见）
- 日志文案（文档引用了日志原文的除外）

拿不准时的裁决问题：**"一个只读文档不读代码的人，行为会因此错误吗？"** 会 → 可见；不会 → 噪音，但可列入报告的"低优先级观察"。
